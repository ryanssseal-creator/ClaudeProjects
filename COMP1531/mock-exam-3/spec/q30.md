# Q30. Swipe Access (10 marks)

You've just started your internship in the team that maintains UNSW's building access system. Your team has recently taken ownership of a critical repository that handles swipe card logic, however, some sections of the codebase are quite old and lack tests. Your manager has tasked you with writing tests for the `accessService` function in `q30/access.ts`. This function is responsible for deciding whether a swipe card should open a door based on the user's details and information about the door.

## Task

Your task is to write tests to cover the given program.

## Part 1 - Basic Coverage (7 marks)

In `q30/access.test.ts`:

- Write tests for the `accessService` function.
- Your goal is to achieve 100% statement, branch, function and line coverage in `access.ts`.

Notes:

- You may only make 1 function call per test.
- You can assume that the implementation is correct when writing your tests.
- Your test clarity/design will not be assessed. We are only assessing coverage.

### Testing

You can use the following command to run the tests and generate a coverage report:

```
npm run test-unit
```

## Part 2 - HTTP Coverage (3 marks)

In `q30/server.test.ts`:

- Write HTTP tests for the `/campus/access` route in `q30/server.ts`.
- Your goal is to achieve 100% statement coverage in `access.ts` and `server.ts`.

Notes:

- You can assume that the implementation is correct when writing your tests.
- Your test clarity/design will not be assessed. We are only assessing coverage.

Hint: consider how you might use part 1 of this question.

### Testing

You can run the following command to start the server with a coverage report
(the report is printed when you stop the server with Ctrl+C):

```
npm run start-coverage
```

You can use the following command to run your http tests:

```
npm run test-server
```

## Submission

Only `q30/access.test.ts` and `q30/server.test.ts` are collected. All other files are replaced in automarking.
