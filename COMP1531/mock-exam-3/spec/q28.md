# Q28. Signup (6 marks)

A study-group app is about to open registrations. Before a new account is created, the signup has to pass some basic checks: every detail must be present, the username and email must be well formed, the password must not be trivially weak, and the user must be old enough.

You have been asked to automate the validation of signups so that only valid ones are passed on for email verification.

## Task

Complete the function in `q28/signup.ts`, based on the function header comments and the interface below.

- You should NOT modify function prototypes or parameters. You can validate this by checking all provided tests pass.

## Interface

**`validateSignup(signup)`** validates a signup against specific criteria.

Parameters: `signup` - the signup to validate.

The checks are made **in the order listed**. The first check that fails throws an `Error` with the EXACT message shown.

| # | Thrown error (EXACT message) | When |
|---|---|---|
| 1 | `"Incomplete signup. Missing field/s: '<missing field>', '<another missing field>'."` | Any of the `profile` fields are missing on the signup object. Fields are comma-separated and listed in alphabetical order, e.g. `"Incomplete signup. Missing field/s: 'age', 'email'."` |
| 2 | `"Username '<username>' is invalid."` | The username is shorter than 3 characters, longer than 15 characters, or contains a space |
| 3 | `"Email '<email>' is invalid."` | The email does not contain exactly one `@`, or has nothing before the `@`, or has no `.` after the `@` |
| 4 | `"Password is too weak."` | The password is shorter than 8 characters, or does not contain at least one digit |
| 5 | `"User is underage."` | The user is younger than 16 |

On success, return the string:

```
"Signup valid. Proceed to verification."
```

Note: a field is *missing* only if it is not on the object at all. A field that is present with the value `0`, `false` or `''` is not missing.
