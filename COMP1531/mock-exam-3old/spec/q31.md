# Q31. K17 Study Rooms (10 marks)

The study rooms on level 1 of K17 are booked by writing your name on a whiteboard outside each door, which works exactly as well as you would expect. CSE has asked for a proper booking system, and the design of its API has fallen to you.

A basic API already exists which allows users to sign in and view rooms, and allows admins to add rooms.

## Existing API

### `POST /auth/login`

Authenticates a user, returning a unique session token and their role in the system.

- **Body**: `{ "zid": "z1234567", "password": "hunter42" }`
- **200**: `{ "session": "a complex and secure session token", "role": "STUDENT" }` (role is `STUDENT` or `ADMIN`)
- **400**: `INVALID_CREDENTIALS` zID and zPass combination fails to authenticate with UNSW single-sign-on.

### `POST /rooms`

Add a study room to the system.

- **Header**: `session`
- **Body**: `{ "name": "K17 113", "capacity": 6 }`
- **200**: `{ "roomId": 1234 }`
- **400**: `INVALID_NAME` Name is empty or longer than 30 characters. `INVALID_CAPACITY` Capacity is less than 1.
- **401**: `UNAUTHORISED` Session is empty or invalid.
- **403**: `FORBIDDEN` Session corresponds to a user whose role is not `ADMIN`.

### `GET /rooms`

Returns a list of all study rooms.

- **Header**: `session`
- **200**: `[ { "roomId": 1234, "name": "K17 113", "capacity": 6 } ]`
- **401**: `UNAUTHORISED` Session is empty or invalid.

### `GET /room/{roomId}`

Get information about one room.

- **Path**: `roomId`
- **Header**: `session`
- **200**: `{ "roomId": 1234, "name": "K17 113", "capacity": 6 }`
- **401**: `UNAUTHORISED` Session is empty or invalid.

All error responses have the body `{ "error": "ERROR_TYPE", "message": "A helpful and descriptive error message" }`.

However, the API is still missing all functionality for actually booking a room.

## User stories

CSE interviewed students and staff and created the following user stories:

1. As a student, I want to book a room on a given date between a start time and an end time so that my group has somewhere to work.
2. As a student, I want to see the times a room is already booked on a given date so that I can choose a free time.
3. As a student, I want to see a list of my own bookings so that I know where I need to be.
4. As a student, I want to cancel one of my bookings so that someone else can use the room.
5. As a student, I want the system to prevent invalid operations, including booking a time that overlaps an existing booking for that room, booking for longer than 2 hours, and cancelling a booking that is not mine.
6. As an admin, I want to be able to cancel any booking so that a room can be freed up for maintenance.
