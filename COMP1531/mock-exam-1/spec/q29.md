# Q29. Campus Events (14 marks)

Arc runs hundreds of events each term, and the spreadsheet they use to track them has finally collapsed. The team wants an application that lets them add events, look them up, and adjust capacities when a bigger room becomes available. You've volunteered to build the server.

The backend functions have already been written for you in `q29/events.ts`. Read them: their parameters, return values and error names tell you most of what you need.

## Task

In `q29/server.ts`, implement the routes specified in the interface below.

Every error response has the body `{ "error": "ERROR_NAME", "message": "..." }`, exactly as returned by the backend function.

## Interface

### `DELETE /clear`

Clear all events. (Already implemented.)

- **200**: `{}`

### `POST /event/add`

Add a new event.

- **Body**: `{ "title": "Trivia Night", "category": "Social", "capacity": 80 }`
- **200**: `{ "eventId": 0 }`
- **400**: `INVALID_TITLE`, `INVALID_CATEGORY`, `INVALID_CAPACITY`, `DUPLICATE_EVENT`

### `GET /event/filter`

Get all events in a category, in descending order of capacity.

- **Query**: `category` (string), e.g. `/event/filter?category=Social`
- **200**: `{ "events": [ { "eventId": 0, "title": "Trivia Night", "category": "Social", "capacity": 80 } ] }`
- **400**: `INVALID_CATEGORY`

### `GET /event/list`

Get events by a list of ids, in the order the ids were given.

- **Query**: `eventIds` (string of comma-separated numbers), e.g. `/event/list?eventIds=2,0,1`
- **200**: `{ "events": [ ... ] }`
- **400**: `INVALID_EVENT_ID`

### `PUT /event/{eventid}`

Update the capacity of one event.

- **Path**: `eventid` (number)
- **Header**: `role` (string)
- **Body**: `{ "capacity": 120 }`
- **200**: `{}`
- **400**: `INVALID_EVENT_ID`, `INVALID_CAPACITY`
- **403**: `INVALID_ROLE`

### `PUT /event/all`

Increase the capacity of every event by `extraCapacity`.

- **Header**: `role` (string)
- **Body**: `{ "extraCapacity": 10 }`
- **200**: `{}`
- **400**: `INVALID_EXTRA_CAPACITY`
- **403**: `INVALID_ROLE`
