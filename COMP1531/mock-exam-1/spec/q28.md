# Q28. Parcel (6 marks)

A courier company receives thousands of parcel bookings each day. Before a parcel can be dispatched, its booking must pass some basic checks: every detail must be present, the tracking ID must be well formed, and the parcel must be something the courier can actually carry.

You have been asked to automate the validation of parcel bookings so that only valid parcels are sent on for dispatch.

## Task

Complete the function in `q28/parcel.ts`, based on the function header comments and the interface below.

- You should NOT modify function prototypes or parameters. You can validate this by checking all provided tests pass.

## Interface

**`validateParcel(parcel)`** validates a parcel booking against specific criteria.

Parameters: `parcel` - the parcel booking to validate.

The checks are made **in the order listed**. The first check that fails throws an `Error` with the EXACT message shown.

| # | Thrown error (EXACT message) | When |
|---|---|---|
| 1 | `"Incomplete parcel. Missing field/s: '<missing field>', '<another missing field>'."` | Any of the `details` fields are missing on the parcel object. Fields are comma-separated and listed in alphabetical order, e.g. `"Incomplete parcel. Missing field/s: 'fragile', 'weightKg'."` |
| 2 | `"Tracking ID '<trackingId>' is invalid."` | The tracking ID is not exactly 10 characters long, or does not start with `AU` |
| 3 | `"Weight of '<weightKg>'kg is out of range."` | The weight is 0 or less, or is more than 22 |
| 4 | `"Postcode '<destinationPostcode>' is invalid."` | The postcode is not a 4 digit number (1000 to 9999 inclusive) |
| 5 | `"Fragile parcels must declare a value."` | The parcel is fragile and its declared value is 0 |

On success, return the string:

```
"Parcel accepted. Ready for dispatch."
```

Note: a field is *missing* only if it is not on the object at all. A field that is present with the value `0` or `false` is not missing.
