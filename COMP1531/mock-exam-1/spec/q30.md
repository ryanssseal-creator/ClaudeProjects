# Q30. Door List (10 marks)

You've just started your internship at a company that develops ticketing software for live music venues. Your team has recently taken ownership of a critical repository that handles entry at the door, however, some sections of the codebase are quite old and lack tests. Your manager has tasked you with writing tests for the `entryService` function in `q30/entry.ts`. This function is responsible for deciding whether a guest should be let into a venue based on the guest's details and the venue's settings for the night.

## Task

Your task is to write tests to cover the given program.

## Part 1 - Basic Coverage (7 marks)

In `q30/entry.test.ts`:

- Write tests for the `entryService` function.
- Your goal is to achieve 100% statement, branch, function and line coverage in `entry.ts`.

Notes:

- You may only make 1 function call per test.
- You can assume that the implementation is correct when writing your tests.
- Your test clarity/design will not be assessed. We are only assessing coverage.

### Testing

You can use the following command to run the tests and generate a coverage report:

```
npm run test-unit
```

## Part 2 - HTTP Coverage (3 marks)

In `q30/server.test.ts`:

- Write HTTP tests for the `/events/entry` route in `q30/server.ts`.
- Your goal is to achieve 100% statement coverage in `entry.ts` and `server.ts`.

Notes:

- You can assume that the implementation is correct when writing your tests.
- Your test clarity/design will not be assessed. We are only assessing coverage.

Hint: consider how you might use part 1 of this question.

### Testing

You can run the following command to start the server with a coverage report
(the report is printed when you stop the server with Ctrl+C):

```
npm run start-coverage
```

You can use the following command to run your http tests:

```
npm run test-server
```

## Submission

Only `q30/entry.test.ts` and `q30/server.test.ts` are collected. All other files are replaced in automarking.
